## 0. 阶段目标与边界

M1 的目标是把“报告 → 用户形成判断 → AI 陪练”从可演示的 MVP 闭环，升级为更易进入、更可探索、更有沉浸感的思辨体验。M1 仍以用户作者性、来源可追溯、诚实降级和可恢复会话为不可突破的底线。

M1 在以下前提全部满足后启动：GitHub #23 的历史材料再生成闭环与其边界修复 #30 均已纳入基线；真实 Zhihu、LLM、Neon 与 Vercel 环境的端到端验收已有明确通过或受控阻塞结论；现有质量门禁仍全绿。刘看山 P2 已拆为 #47/#48，不阻塞 M1。

### M1 承诺

1. 重做知识图谱：从报告结构化抽取实体与关系，并以可访问的力导向图呈现。
2. 交付快速诘问：先帮助用户理解报告和形成判断，再以有限回合完成目标导向追问。
3. 交付深度诘问：在同一引擎上启用完整八策略、强度递进与可追溯认知轨迹。
4. 交付趣味模式：通过角色化语言与刘看山状态反馈增加表现力，不复制业务状态机。
5. 交付收束型 GalGame：通过短篇虚构情境把思辨嵌入选择，并能桥接回诘问。

### 非目标

- agent 内部知识库、语义检索、论证/陷阱提示；这些排在 M1 之后。
- 相关推荐、语音、数字人、分享、跨设备、游客认领与正式账户。
- 开放式长剧情、自由探索、长期可返回的 GalGame 独立入口。
- 观点质量评分、人格诊断、认知升级结论，或把 AI 内容归因为用户。

## 一、M1 用户主链路

```text
问题/热榜
  → 多源报告与真实引用
  → 结构化知识图谱（可探索但不阻塞阅读）
  → 选择已实现模式：快速 / 深度 / 趣味 / GalGame
  → 定向或剧情入口
  → 用户显式选择下一步
  → 正式诘问或关键剧情选择
  → 可保存退出、正常收束或回到报告
```

模式入口只展示已经实现的模式。AI 可以推荐模式或动作，但不能自动替用户选择、切换模式或宣告用户已经形成了某种观点。

## 二、知识图谱重做

### 2.1 用户价值

用户应能在报告旁看清核心议题、关键概念、主要主张和相关行动者怎样连接，而不是只看到从来源标题拼出的列表。图谱是报告的可检查结构视图，不是独立事实来源。

### 2.2 结构化抽取契约

`GraphExtractionProvider` 在报告生成后从报告正文、观点与既有 citations 一次性抽取并校验图谱。节点类型固定为：

- `topic`：核心议题；
- `concept`：关键概念、制度、技术或现象；
- `claim`：报告中的主要观点或争议判断；
- `actor`：组织、群体、人物或利益相关方。

边在数据中保留 `subject`、`predicate`、`object` 和方向；谓词限于受控词表，例如支持、反驳、导致、依赖、影响、对比、主张。每个节点包含规范化名称、简短说明、类型及关联 citation IDs；每条边包含来源类型：`supported`、`inferred` 或 `user_claimed`。

`supported` 边必须引用报告已有 citation；`inferred` 与 `user_claimed` 必须明确标识，不能冒充被来源证实的事实。输出不通过 schema、节点/边引用校验或安全校验时，使用确定性文本抽取的简化图并披露降级；图谱出错绝不阻塞报告。

### 2.3 视觉与交互

- 使用无箭头的力导向图：画布只展示节点和节点间连接，不在线条上堆标签。
- 选择节点或连接后，详情面板显示关系类型、数据方向、来源类型、说明及真实 citations。
- 节点可用键盘聚焦和激活；详情面板提供与画布等价的信息，不能只依赖颜色或位置。
- 自动化验收验证结构、选择和详情内容，不断言不稳定的像素位置。
- 小屏幕上允许缩放、拖动与详情抽屉；图谱不能遮挡报告引用阅读。

## 三、统一模式与定向阶段

### 3.1 ModeConfig

快速、深度与趣味模式使用同一状态机，以 `ModeConfig` 描述而非复制流程：

- `orientationMaxRounds`
- `allowedStrategies`
- `checkpointPolicy`
- `intensityPolicy`
- `presentationStyle`

现有标准诘问演进为默认的快速诘问。旧会话保持原有持久化语义，恢复时不会被插入新阶段或改写完成态。

### 3.2 定向阶段

新会话在观点选择后进入 `orientation`：最多两轮报告理解、比较或观点澄清。定向回答保留为用户消息，可成为成果卡证据，但不计入正式诘问轮数、策略历史或检查点。

两轮后必须进入 `transitionChoice` 并展示轻量选择卡。固定动作类型为：

- `challenge_claim`：开始挑战当前判断；
- `inspect_evidence`：先检查判断依据；
- `inspect_counterargument`：先理解最强反方；
- `continue_orientation`：继续梳理报告。

LLM 只能生成中性摘要、具体选项文案和推荐动作；服务端校验动作类型、数量、来源与安全文案。用户点击才推进状态。LLM 失败时使用人工审核模板，因此选择卡始终可用。

## 四、快速诘问

快速诘问是 M1 的默认且较浅模式：最多两轮定向，随后 3–5 轮目标导向正式追问。

用户选择或接受 AI 推荐的目标类型：

- `clarify_position`：厘清当前观点与理由；
- `weigh_decision`：比较现实选择的收益、代价与前提；
- `refine_expression`：为回答、答辩、演讲或重要沟通打磨表达。

目标只改变首轮策略优先级与结束回顾组织，不改变来源、作者归因、退出、完成态和“不替用户裁决”护栏。用户可在定向或正式诘问阶段退出；未完成会话保留可恢复状态。

---

## 五、深度诘问与认知轨迹

深度模式复用定向、选择卡、来源和完成规则，但开放八种策略：M1 证据追问、M2 前提追问、M3 锚定揭露、M4 钢铁人反驳、M5 系统二激活、M6 立场反转、M7 元认知、M8 立场崩塌检测。

它通过策略组合、难度递进和更长阶段检查点支持深思，不以更激烈的语言替代更好的提问。每项策略都需有与当前用户表达相连的 LLM prompt、人工审核 fallback 模板、适用条件和越权拒绝规则。

认知轨迹仅记录可追溯的用户表达变化：`claim`、`evidence`、`premise`、`counterargument`、`unresolved_question`。每项必须关联用户消息 ID 或显式选择的观点；AI 只能整理比较，不能诊断人格、评分或虚构变化。检查点与正常完成时更新轨迹，并可在成果卡查看。

---

## 六、趣味模式与角色

趣味模式是快速/深度模式的表现层，不创建独立状态机。首次交付固定以快速模式为底层节奏；深度底层的趣味体验需在深度模式稳定后另立决策。

用户在会话创建时从三名内置角色中选择其一：

- 轻松朋友：鼓励、口语化、低压力追问；
- 古风辩友：克制、典雅，以反问和类比推进；
- 二次元搭档：活泼，但不幼化或回避严肃议题。

角色配置包含名称、简介、语气约束、禁用表达与视觉资源引用。首版所有角色共用刘看山资源，差异仅来自语言与状态文案；视觉资源接口为未来角色扩展保留。角色一经选择即持久化且不可在同一会话切换；用户要换角色须从同一报告新开会话。

角色绝不能改变策略、证据、选择卡动作、轮次、检查点、退出、成果卡归因或 AI 护栏。

## 七、GalGame 情境化思辨

### 7.1 体验边界

GalGame 是从当前报告、真实引用与用户初步倾向生成的独立虚构短篇。首版单场景在约 15 分钟内收束，包含 3–5 个关键抉择与少量小决策。关键选择通常留给用户 5–15 秒思考。虚构剧情、角色台词和后果始终显式标为 AI 生成，不能冒充外部来源或用户事实。

AI 只可从预设世界观选择：

- `future_city`：近未来科技社会；
- `fantasy_realm`：架空城邦或魔法秩序；
- `alternate_campus`：架空校园或青年社群。

它必须说明匹配理由；服务端只接受模板 ID。

### 7.2 剧情骨架与关键决策

采用有限分支、阶段汇合的三幕骨架：开场冲突与角色目标；第一幕一个关键抉择；第二幕一至两个关键抉择并呈现反方代价或证据冲突；第三幕一至两个关键抉择后收束。开始时生成并持久化完整骨架；逐幕展开台词与小决策，恢复时不得重新生成或改写既有路径。

关键决策要映射采信证据、接受前提、权衡代价、回应反方或修正立场。每个选项显示剧情后果预览与固定提示：真实 `evidence` citation，及明确属于推演的 `premise`、`benefit`、`cost`。小决策不展示完整提示，且不产生无限分支。

### 7.3 结束态

`StoryRun` 仅有：

- `in_progress`：保存并退出回到报告页，可恢复；
- `completed`：正常收束，展示剧情结局与不评分的思辨回顾；
- `ended_early`：直接结束，保留“未收束结束”的过程，不生成虚假结局或成果卡，且不可恢复。

完成后用户可将最终取舍桥接到标准/深度诘问、回到报告，或仅保存剧情。开放世界、可长期返回的独立入口和自由探索不属于 M1。

### 7.4 叙事研究与降级

开发先完成 G0：研究短篇三段式节奏、有限分支/阶段汇合、关键抉择后果与互动叙事收束，并把每项理论转为有来源、版本、适用范围和测试样例的规则。故事资产与材料许可在进入仓库或部署前确认。

生成器使用“受策展的叙事骨架 + AI 话题化实例”，以 schema 校验世界观、幕数、关键决策数、真实引用和安全文本。LLM 不可用、骨架非法或内容不安全时，返回预置短篇模板，不能阻塞用户。

## 八、数据、平台与降级约束

- M1 新增的图谱、模式状态、定向选择卡、认知轨迹、角色和 `StoryRun` 均须在 `Session` 中持久化，并保持旧会话兼容。
- 已完成会话不可改写；所有新阶段与结束态均由服务端状态机拥有唯一写权。
- 真正改变 Neon 表结构、添加索引、启用 Vercel 环境变量或接入新的外部供应商前，必须先提交平台变更说明并获得确认：操作步骤、迁移/回滚、成本、密钥、隐私与本地降级缺一不可。
- M1 不接入知识库语义检索；因此不引入 `pgvector`、embedding API 或其表结构。

## 九、拆票、阻塞与两人协作

```text
M1-00 准入门禁
  → KG1 图谱数据契约与抽取
  → KG2 力导向图与详情/无障碍
  → KG3 图谱端到端验收
  → F1/F2/F3/F4 快速诘问
  → D1/D2/D3/D4 深度诘问
  → U1/U2 趣味角色
  → G0/G1/G2/G3/G4/G5 GalGame
```

- **KG1**：`GraphExtractionProvider`、schema、来源校验、简化图 fallback、持久化兼容。
- **KG2**：力导向画布、节点/连接选择、详情面板、键盘等价交互。
- **KG3**：抽取、降级、恢复、来源与 UI E2E。
- **F1–F4**：模式契约、定向选择卡、快速编排、全链路验证。
- **D1–D4**：M3/M5、M7/M8、深度调度与轨迹、E2E。
- **U1–U2**：角色配置/锁定和趣味呈现/验证。
- **G0–G5**：叙事研究、`StoryRun` 契约、生成与降级、UI、结束态桥接、E2E。

始终只进行一个会触及状态机、Provider 或数据库的主实现票。另一方并行准备下一票的目标场景、2–3 个正例、一个反例、内容/许可审核与手工验收脚本。每个 ticket 必须以 GitHub Issue 为编号、范围、依赖和状态的唯一权威来源。

## 十、M1 验收门禁

除现有 typecheck、lint、unit/integration test、build 与 E2E 门禁外，M1 必须证明：

1. 图谱节点、关系、详情与真实 citations 对应；抽取失败不会阻塞报告。
2. 新会话在两轮定向后出现选择卡，AI 不能擅自进入挑战；旧会话不被改写。
3. 快速模式在 3–5 轮内按目标完成，所有 fallback、退出与恢复诚实可用。
4. 深度模式的八策略均有可验证的适用条件、fallback 和作者性护栏；轨迹只引用用户表达。
5. 角色不可中途切换，且角色化表现不改变思辨业务规则。
6. GalGame 在 15 分钟级别、3–5 个关键选择内正常收束；三种结束态、证据提示、恢复和诘问桥接正确。
7. 任意 LLM/图谱/剧情失败都有可披露的降级路径，且不伪称真实持久化、引用或用户观点。
