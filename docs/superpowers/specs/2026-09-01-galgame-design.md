# GalGame 情境化思辨设计

日期：2026-09-01  
状态：已确认；实现受 M1 准入门禁与 GitHub Issues 约束

## 目标与范围

GalGame 是知研在报告与用户初步倾向之上，生成相对独立的虚构剧情场景、把思辨嵌入选择的模式。它不是普通诘问的换皮，也不是开放式游戏。

第一版是可在约 15 分钟内收束的单场景短篇。用户连续阅读时，每个关键决策预留约 5–15 秒思考；全程有退出入口。开放式长剧情、自由探索与可长期返回的独立入口属于 Demo 后的独立项目，不提前实现。

## 输入、世界观与事实边界

输入为当前报告、其真实引用、用户已表达的观点，以及可选的初始倾向。AI 从受控预设中自动选择最贴合话题冲突的世界观，并生成选择理由；服务端只接受预设 ID。

首批世界观模板：

- `future_city`：近未来科技社会，适合算法、职业、教育、公共资源等议题。
- `fantasy_realm`：架空城邦或魔法秩序，适合权力、伦理、规则与群体冲突。
- `alternate_campus`：架空校园或青年社群，适合成长、关系、竞争与身份议题。

报告来源与用户表达是事实/归因依据；角色、事件、台词和剧情后果均须明确标为 AI 生成的虚构情境，绝不伪装为知乎、全网或用户事实。

## 叙事结构与时长

采用“有限分支、阶段汇合”的短篇结构：

```text
开场：冲突与角色目标
  → 第一幕：1 个关键抉择 + 少量探索
  → 第二幕：1–2 个关键抉择，呈现反方代价或证据冲突
  → 第三幕：1–2 个关键抉择，形成最终取舍
  → 收束：剧情结局与思辨回顾
```

全篇有 3–5 个关键抉择。每个关键抉择映射采信证据、接受前提、权衡代价、回应反方或修正立场等思辨动作。小决策可更多，但只用于探索信息、理解角色或影响叙述细节；不创建无限剧情树。不同分支在下一幕汇合，仅保留少量状态变量（例如已获证据、角色信任、已承认的取舍）。

故事开始时生成并持久化完整剧情骨架；逐幕展开台词与小决策。恢复时绝不重新生成或改写已发生的故事。

## 决策卡与来源披露

关键决策的每个选项显示简短的剧情后果预览，以及固定思辨提示：

- `evidence`：只可引用当前报告中真实来源；没有可靠来源时标记“待验证”。
- `premise`：该选择隐含接受的条件。
- `benefit`：可能得到的收益。
- `cost`：可能承担的代价。

前提、收益和代价是推演，必须与事实证据区分。小决策不展示完整提示，避免打断阅读节奏。

## 结束态与桥接

`StoryRun` 有三种结束态：

- `in_progress`：用户“保存并退出”后回到报告页，可稍后恢复。
- `completed`：用户正常收束；显示 AI 生成的剧情结局与不评分的思辨回顾。
- `ended_early`：用户选择直接结束；保留过程并标注“未收束结束”，不生成虚假结局或成果卡，不可恢复。

正常收束后，用户可选择：以剧情中的最终取舍进入标准或深度诘问、回到报告页、或仅保存该已完成剧情。剧情回顾必须区分虚构后果、用户表达与报告证据，不能把剧情后果归因为用户观点。

## 生成、降级与安全

采用“策展的叙事骨架 + AI 按话题实例化”：预定义世界观框架、冲突类型、角色功能、三段式节奏和收束规则；AI 只生成话题相关的事件、细节、台词与选项文案。

生成器输出受固定 schema 限制，服务端校验世界观、幕数、关键决策数、动作类型、真实来源引用和文案安全性。剧情骨架不合格、LLM 不可用或内容不安全时，降级为预置短篇模板，不能阻塞用户。

## 拆票与依赖

| Ticket | 范围 | 依赖 |

| G0 | 叙事理论研究与内容规范：短篇节奏、分支、关键抉择、收束、来源记录 | 无 |
| G1 | `StoryRun` 数据契约：世界观、骨架、决策、状态变量、结束态 | G0 |

## 验收

- AI 只从三种预设世界观中选择，且场景与话题冲突相关。
- 一次完整短篇有 3–5 个关键抉择，并在约 15 分钟内可完成。
- 每个关键抉择的证据只解析到真实报告来源；前提、收益、代价均标明为推演。
- 小决策不产生无限分支；不同分支按骨架在下一幕汇合。
- 刷新及保存退出后恢复同一骨架、同一已选路径和同一待选决策。
- 三种结束态的恢复、只读及成果语义正确。
- 正常收束可桥接至标准/深度诘问；直接结束不伪造结局或成果卡。
- LLM 失败和非法剧情骨架均有可用模板降级。

## 协作方式

G0 由双方共同完成：Codex 检索并提炼可靠的互动叙事理论，形成可执行生成规则；用户审核叙事节奏、世界观和关键抉择是否服务知研的思辨目标。后续保持一个状态机/Provider 主实现票；另一方并行准备下一票的体验样例、反例和人工验收脚本。
