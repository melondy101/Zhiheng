# 后 MVP 产品决策

日期：2026-09-01  
状态：已决策；后续实现前需按各自规格补全验收细节

## 已确定主线

```text
MVP 收尾与真实环境验收
  → 知识图谱重做
  → 快速诘问（替代新会话的原标准入口）
  → 深度诘问
  → 趣味模式与角色
  → GalGame
  → agent 内部知识库
```

相关推荐、语音、游客认领/正式账户、分享和跨设备访问不纳入当前排期。

## 知识图谱重做

报告生成时由新的服务端 `GraphExtractionProvider` 从报告正文、观点和现有引用中一次性抽取结构化实体及关系，并把图谱随 `Session` 持久化。抽取结果必须使用固定 schema：节点包括规范化名称、类型、摘要与引用 ID；边包括 `subject`、`predicate`、`object`、关系来源类型和引用 ID。

关系方向只存储于数据中；视觉层使用无箭头的力导向图，只显示节点和连接。选中节点或连接后，详情面板展示关系类型、方向语义、来源和真实引用。支持性关系必须指向报告已有 citation；推断和用户主张必须明确标记，不能伪装为事实。

LLM 结构化抽取失败、schema 校验失败或来源校验失败时，使用确定性文本抽取的简化图并明确披露；图谱失败不能阻塞报告。前端使用可访问的力导向布局，提供键盘可聚焦节点/连接和等价详情；自动化测试验证结构与详情语义，不依赖不稳定的像素坐标。

## 模式入口与定向阶段

新创建的会话不再向用户展示独立的“标准诘问”入口：现有标准流程演进为默认的**快速诘问**。旧会话保留其已持久化语义，恢复时不插入新的定向阶段。

快速、深度与趣味模式均使用相同的定向阶段：最多两轮报告理解/观点澄清，随后必须展示固定动作类型的选择卡。AI 可生成受约束的摘要、选项文案和推荐动作，但只有用户选择才能进入正式诘问。GalGame 使用其独立的剧情入口和状态机。

报告完成后的模式入口只展示已实现的模式；未来模式不显示禁用入口。AI 可推荐模式，但不能自动替用户选择。

## 快速诘问

快速诘问是默认且较浅的模式，采用 3–5 轮目标导向的正式追问。开始前提供固定目标类型，并默认推荐“澄清当前观点”：

- `clarify_position`：厘清当前观点与理由。
- `weigh_decision`：比较现实选择的收益、代价和前提。
- `refine_expression`：为回答、答辩、演讲或重要沟通打磨表达。

用户可接受推荐或自行选择目标；目标决定首轮优先策略与结束回顾的组织方式，不改变来源、作者归因、退出、完成态和“不替用户裁决”护栏。

## 深度诘问与认知轨迹

深度诘问在快速模式的定向契约上扩展到八种策略、强度递进和更长的阶段检查点。它不产生人格诊断、思维评分或“认知升级”结论。

认知轨迹只记录用户可追溯表达的变化事件：`claim`、`evidence`、`premise`、`counterargument`、`unresolved_question`。每个事件必须关联用户消息 ID 或显式选中的观点；AI 可组织和比较事件，但不得凭空推断变化。轨迹在检查点和正常完成时更新，用户可在成果卡中查看。

## GalGame 研究规范

G0 的产出是受版本控制的叙事规则与测试样例，不是直接生成大量剧本。研究至少覆盖短篇三段式节奏、有限分支/阶段汇合、关键抉择的后果设计和互动叙事收束；每项规则记录来源、适用范围和如何转化为生成/验证约束。

用户负责审核世界观、节奏和关键抉择是否服务思辨；Codex 负责将研究结论转换为受控 schema、生成规则、模板降级和自动化验收。故事资产及理论材料的许可必须在纳入仓库或部署前确认。

## 实施前平台变更

需要 Neon、Vercel、embedding 供应商或数据库迁移的知识库实现，必须先通过 `docs/architecture.md` 的“外部平台与数据库变更门禁”；未获用户确认不得操作外部平台或生产数据。
